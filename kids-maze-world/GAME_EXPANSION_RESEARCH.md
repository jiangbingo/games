# 迷宫小小探险家：儿童游戏类型扩展调研

> **结论先行**：不建议把现有产品直接扩展为依赖反应速度、双手协调、精细拖拽、复杂物理或开放聊天的“游戏集合”。最合适的方向是把“森林邮局”扩展为一组 **3–8 分钟、单一目标、可反复尝试、以点击/滑动为主的 guided-play 微游戏**。优先开发“森林路线拼图”和“邮包配对”，随后扩展“分类小站”和“数数石桥”。

## 1. 调研范围与现有约束

当前项目面向约 5 岁儿童，已经拥有 120 个迷宫、12 个森林主题、Babylon 2D 画布、真实环境音、主题音色、贴纸奖励、家长面板、本地周报与 iPad 横竖屏适配。扩展玩法必须保留“轻量、无失败惩罚、低挫败、亲子可解释、无需登录、数据只在本机”的边界。

对 3–5 岁儿童，触摸交互应优先使用**大尺寸点击、滑动和低精度拖动**；小目标、精细鼠标拖拽、快速反应和双手同时操作会显著提高操作挫败。NN/g 的儿童可用性研究建议年轻儿童的触控目标至少约 2cm×2cm，并强调可以为同一目标提供点击和拖动等灵活操作方式。[1]

从学习与产品定位看，适合的不是“练习题换皮”，而是让儿童保有选择和探索的 guided play：产品用故事、提示和可控难度把目标嵌入游戏，但不通过倒计时、扣分或失败动画压迫儿童。NAEYC 将这种模式描述为同时保留儿童能动性和明确学习目标的游戏化引导。[2]

## 2. 候选玩法总表

评分为本项目的相对评估，不代表外部市场数据。`复用度`越高越好；`新资产`、`工程复杂度`、`挫败风险`越低越好。

| 候选玩法 | 核心交互与能力 | 适龄性 | 现有复用度 | 新资产需求 | 工程复杂度 | 挫败风险 | 建议优先级 |
|---|---|---:|---:|---:|---:|---:|---|
| **森林路线拼图** | 点按/滑动旋转路径块，让小狐狸或邮车连通起点与终点；空间推理。 | 5/5 | 5/5 | 1/5 | 2/5 | 1/5 | **P0** |
| **邮包配对** | 翻两张大卡，匹配主题角色、终点物或邮票；记忆与观察。 | 5/5 | 5/5 | 1/5 | 1/5 | 1/5 | **P0** |
| **分类小站** | 先点物品，再点颜色/形状/主题篮筐；分类、词汇和规则理解。 | 5/5 | 4/5 | 2/5 | 2/5 | 1/5 | **P1** |
| **数数石桥** | 通过 1–10 的连续点按或选择正确数量，帮助角色过河；数感与一一对应。 | 5/5 | 4/5 | 2/5 | 2/5 | 1/5 | **P1** |
| **花园浇灌顺序** | 用 2–4 步顺序卡安排浇水/播种/收获；序列、计划和执行功能。 | 4/5 | 4/5 | 2/5 | 3/5 | 2/5 | **P1** |
| **森林找一找** | 在低密度主题图中点出 3–5 个明确物件；视觉搜索和词汇。 | 4/5 | 4/5 | 2/5 | 2/5 | 2/5 | **P2** |
| **萤火节奏回声** | 听 2–4 拍，按同序点亮大萤火；听觉记忆和节奏。 | 4/5 | 3/5 | 2/5 | 3/5 | 2/5 | **P2** |
| **影子与物品** | 点选物品与轮廓配对；形状辨识与视觉匹配。 | 4/5 | 4/5 | 2/5 | 2/5 | 2/5 | **P2** |
| **森林故事拼图** | 3–6 片大块拼图，点击交换位置而非精细拖动；整体/部分关系。 | 4/5 | 3/5 | 3/5 | 3/5 | 2/5 | P3 |
| **自由贴纸场景** | 点选贴纸放入森林场景并讲故事；创造表达。 | 4/5 | 3/5 | 4/5 | 3/5 | 1/5 | P3 |

## 3. 首选玩法详解

### 3.1 P0：森林路线拼图

孩子点击大尺寸路径块旋转方向，将“邮局—森林—终点”连成一条路线；连通后由小狐狸自动走完路线并触发短故事。它延续现有迷宫的空间理解，但不要求儿童连续控制角色，难度可通过 3×3、4×4、5×5 网格和可旋转块数量稳定调整。

| 维度 | 设计建议 |
|---|---|
| 操作 | 单击旋转；可选长按提示；不要用拖拽摆放作为唯一交互。 |
| 低挫败 | 永远允许重试；错误状态只用温和的“这条小路还没接上”反馈，不扣星、不倒计时。 |
| 复用 | `GameWorld` 的“起点—目标—路径—完成”抽象、Babylon 正交画布、`SoundManager`、主题文案、奖励与家长活动记录都可复用。 |
| 新模块 | `RoutePuzzleWorld`、连通性检查（BFS / DFS）、旋转状态、演示动画。 |
| 验证 | 单元测试所有关卡可解、旋转后连通性、提示路径；iPad 检查旋转块触控区。 |

它是最合理的第一项扩展：对儿童来说像“铺一条小路”，对工程来说复用了大多数现有资产与心智模型。

### 3.2 P0：邮包配对

界面展示 4–8 张大卡，点击两张卡寻找主题角色、终点物、邮票或森林道具的配对。第一轮建议始终使用 4 对以内，并允许“翻开后停留一小段时间”而非快速翻回；儿童成功后获得该主题的小邮戳。

| 维度 | 设计建议 |
|---|---|
| 操作 | 单击翻卡；不要要求双击、快速点击或小卡片。 |
| 低挫败 | 未匹配卡停留约 1 秒再温和盖回；提示可翻出一对。 |
| 复用 | 12 张主题插画可裁切/派生为卡面；复用贴纸、主题音色、家长记录与 CSS 弹层。 |
| 新模块 | `MemoryMatchWorld` 或纯 React 状态机；卡片洗牌应支持固定 seed 便于测试。 |
| 验证 | 确保每局成对、同一张卡不能被选两次、完成状态只触发一次、减少动画模式可用。 |

该玩法不必使用 Babylon；使用 React/DOM 能减少渲染复杂度，并使屏幕阅读器与焦点管理更容易改善。

### 3.3 P1：分类小站

孩子把“要寄的物品”送到对应主题篮筐，例如“蓝莓篮”“花田邮筒”“贝壳箱”。主操作不要强制精细拖拽：采用“**先点物品，再点目标篮筐**”作为默认，拖放仅作为可选捷径。这与儿童触摸动作的可替代性建议一致。[1]

游戏可以自然承载颜色、形状、大小、主题和简单词汇，但每局只能有一个明确维度。例如先做“颜色小站”，不要在同一局混合颜色、形状、数数和英文词汇。

### 3.4 P1：数数石桥

在森林河流上展示 1–10 块大踏石或一组可点亮的萤火。孩子可以点“需要几块石头”、选择正确数量，或带着角色一步一步走；重点是**一一对应**而不是答题速度。数错时给可视化数量提示，保留所有选项，不要写“错误”。

该玩法可复用现有角色、移动音效、通关故事和每日活动，但应单独记录为 `counting` 模式，不要把错误次数写入家长周报。

## 4. 暂不建议优先开发的类型

| 类型 | 不建议原因 | 替代方式 |
|---|---|---|
| 跑酷、躲避、Flappy 类 | 高速反应和连续精细控制，对 5 岁儿童容易造成压力与挫败。 | 改为回合制“选一条安全小路”。 |
| 双摇杆、跳跃平台、自由 3D | 双手协调、镜头控制和空间旋转超出当前核心用户的稳定能力范围。[1] | 保持单指 / 单按钮的正交 2D。 |
| 强制拖拽拼图 | 精确拖到小区域对幼儿困难。 | 用“点选—点目标”或大吸附区域。 |
| 计时竞速、排行榜、连败惩罚 | 与低挫败、隐私和家长可解释性相冲突。 | 用个人故事进度和非竞争性贴纸。 |
| 实时多人、聊天、UGC 分享 | 引入账号、内容审核、隐私和安全成本。 | 保持单机本地游戏；若未来家庭共享，先设计家长导出 / 导入。 |
| 麦克风语音识别、摄像头 AR | 权限、儿童隐私、设备兼容和识别失败成本高。 | 用点按节奏 / 图片探索替代。 |

## 5. 现有架构的复用与建议扩展方式

### 5.1 可复用层

| 现有层 | 可复用能力 | 适合的扩展玩法 |
|---|---|---|
| `themePresentation.ts` | 12 主题图片、角色、终点、故事、音色。 | 全部候选玩法。 |
| `SoundManager.ts` | 用户手势后的音效与环境音、低带宽保护。 | 路线、配对、分类、节奏。 |
| `activity.ts` | 本地日期 / 周报基础。 | 所有新模式，但需先修 UTC 日期不一致。 |
| `ParentPanel.tsx` | 时长、声音、重置与报告入口。 | 聚合所有模式的“完成局数”，不记录错误。 |
| `GameCanvas.tsx` | 主 shell、键盘、贴纸、主题通关流程。 | 可拆出通用 shell；不要继续无边界堆叠新模式逻辑。 |
| `scene.ts` / Babylon | 正交 2D、主题色、动画和网格。 | 路线、数数石桥、可视化探索。 |
| CSS 设计系统 | 森林绘本、iPad 横竖屏、安全区、动效。 | 所有玩法。 |

### 5.2 推荐模块边界

如果扩展到两个以上新模式，应先重构为统一的游戏目录，而不是把新状态继续写进 `GameCanvas.tsx`。

```text
client/src/games/
  shared/
    GameShell.tsx            # 主题、奖励、家长入口、声音解锁
    gameTypes.ts             # 模式、完成事件、统计类型
    useGameProgress.ts       # 本地数据版本和进度写入
  maze/
    MazeWorld.ts             # 从现有 GameWorld 迁移或适配
  route-puzzle/
    RoutePuzzleWorld.ts
    routeSolver.ts
  memory-match/
    MemoryMatchGame.tsx
  sorting-station/
    SortingStationGame.tsx
```

建议先保持一个主页和“森林小站地图”，由家长或儿童点选模式；不要在未验证信息架构前引入复杂路由。每个模式需要有相同的完成事件契约，例如：

```ts
type GameCompletion = {
  mode: "maze" | "route" | "memory" | "sorting" | "counting";
  themeId: number;
  levelId: string;
  completedAt: string;
  rewardId?: string;
};
```

该契约应只记录完成与奖励，不记录错误次数、反应时间或任何可识别儿童行为数据。

## 6. 分阶段路线图

### 阶段 A：稳态化（先于新增玩法）

1. 修复 `scene.ts` 动态材质在重复移动中的累积风险。
2. 统一 `GameCanvas.tsx` 与 `activity.ts` 的本地日期 key。
3. 固化 120 关算法测试并建立 `pnpm test`。
4. 更新资源为版本化文件名或明确缓存策略，改善 iPad 首屏体积。

不完成这一阶段就叠加多种玩法，会让长时间 iPad 使用、数据和发布风险一起扩大。

### 阶段 B：第一批两种玩法

先实现“森林路线拼图”和“邮包配对”。两者覆盖空间推理与观察记忆，且可复用主题图、故事、音效、奖励和家长进度。每一种都先做 10 个可固定 seed 的关卡 / 牌局，建立单元测试和真实 iPad 回归后再扩展到 120 个内容单元。

### 阶段 C：学习型小站

在阶段 B 稳定后增加“分类小站”和“数数石桥”。每次只引入一个学习目标；如果要显示给家长，只报告完成局数和可选主题，不显示“正确率排名”。

### 阶段 D：内容与创作扩展

最后才考虑“森林找一找”“节奏回声”“自由贴纸场景”。这些玩法更依赖新素材、音频授权和内容审核，应先完成 `ASSET_LEDGER.md` 的视觉素材授权补证。

## 7. 每个新玩法的发布门槛

每个模式在进入生产前应满足以下标准：

| 维度 | 最低门槛 |
|---|---|
| 适龄交互 | 所有关键目标在 iPad 上足够大；主路径可用点击 / 滑动完成；无两手协作、无快速反应硬门槛。 |
| 低挫败 | 无倒计时、扣分、连败、广告跳转或不可解释的失败；至少有一个提示 / 重试方式。 |
| 内容 | 主题语义、图片、声音、故事与奖励均适龄，且素材台账状态明确。 |
| 隐私 | 无账号、广告、聊天、外部分享和隐形行为画像；新 localStorage 键有迁移策略。 |
| 工程 | `pnpm check`、`pnpm build`、`git diff --check`、核心逻辑测试通过。 |
| 设备 | iPad Safari 横竖屏实测；桌面键盘不破坏；低带宽下主操作不被音频 / 大图阻塞。 |
| 发布 | Preview 验证、生产健康检查和回滚目标按 `OPS_RUNBOOK.md` 记录。 |

## 8. 推荐的下一项决策

如果目标是以最小风险扩展产品广度，选择 **“森林路线拼图 + 邮包配对”**。如果目标是增强亲子学习价值，第二阶段优先选 **“数数石桥”**，再考虑分类小站。若目标是快速增加视觉内容，应避免先做“找一找”或“自由贴纸场景”，因为当前视觉素材授权与首屏体积仍需补齐。

> 推荐在进入实现前先让产品所有者确认三项：第一批玩法是否为“路线拼图 + 配对”；是否将“每日时长”定位为软提醒；新增模式是否统一使用一个本地进度架构。确认后再执行视觉目标、风险切片、资产计划和 iPad 验证。
