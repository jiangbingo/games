# iPad PWA 离线与全屏体验验证清单

**适用应用：** 迷宫小小探险家

**适用构建：** `feat/ipad-pwa-baseline` 及后续版本

**执行角色：** 家长或测试人员；儿童仅参与可用性观察，不执行系统设置操作

**通过原则：** 关键路径全部通过；若任何“阻断”项失败，不应将该版本作为孩子桌面上的稳定入口。

> Home Screen Web App 需要用户从 Safari 的“分享”菜单选择“添加到主屏幕”；在具备 Manifest 且 `display` 为 `standalone` 或 `fullscreen` 时，打开后会以独立于 Safari 的 App 形态运行。[1]

## 1. 测试前准备

测试应使用 **HTTPS 的预览或生产地址**；不要以本地开发服务器结果替代真实 iPad 验收。开始前记录下表，确保日后能重现设备问题。每轮只测试一个明确的构建版本，避免 Service Worker 缓存混入旧资源。

|---|---|---|
| 测试日期 / 测试人 |  | 例如 `2026-08-26 / bingo`。 |
| URL / Git commit |  | 填预览或生产 URL，以及待测 commit。 |
| iPad 型号 / 屏幕尺寸 |  | 例如 iPad (10th generation)、iPad mini、iPad Air。 |
| iPadOS 版本 |  | 设置 → 通用 → 关于本机。 |
| Safari 状态 |  | 全新安装 / 已存在旧版 / 已清除网站数据。 |
| 网络条件 |  | 稳定 Wi‑Fi、弱网、完全离线。 |
| 测试模式 |  | Safari 标签页 / Home Screen Web App / 横屏 / 竖屏。 |
| 结果与证据 |  | 通过、失败、截图或录屏文件名。 |

测试开始前，确保设备有足够空间；关闭与游戏无关的高负载 App；将系统“自动锁定”临时设为较长时间。若测试版本覆盖旧版，先在家长允许的情况下结束旧 Web App，再打开新 URL；不要在游戏进行中强制刷新。

## 2. 在线基线与安装路径

此组测试先确认普通 Safari 访问无回归，再验证家长可以完成主屏幕安装。儿童主流程不应展示安装说明；该说明仅可在家长面板中查看。

| ID | 操作 | 预期结果 | 级别 | 结果 |
|---|---|---|---|---|
| O-01 | 在 Safari 打开待测 HTTPS URL，等待首屏完成。 | 游戏画面、迷宫、方向控制与静态插画正常出现；无白屏、无限加载或报错提示。 | 阻断 |  |
| O-02 | 点击四个方向键、撤销、重来和提示各一次。 | 控件只触发一次预期动作；页面不滚动、不选中文本、不触发 Safari 缩放。 | 阻断 |  |
| O-03 | 首次轻点开始操作，再打开/关闭音效。 | 第一次用户交互后音效可以播放；静音后游戏仍完整可玩。带声音的媒体或 Web Audio 可能被浏览器的自动播放策略阻止，因此音效不能作为游戏完成前提。[2] | 高 |  |
| O-04 | 打开“家长”面板。 | 可见“添加到 iPad 主屏幕”说明；儿童主界面没有安装弹窗、广告或外链。 | 高 |  |
| O-05 | 在 Safari 点“分享”→“添加到主屏幕”，保持默认名称并确认添加。 | 主屏幕出现图标和名称“小小探险家”；图标清晰、无透明/裁切异常。 | 阻断 |  |
| O-06 | 从主屏幕点击新图标启动。 | 以独立 Web App 打开，不出现 Safari 地址栏、标签栏或首次安装提示。 | 阻断 |  |

## 3. 全屏、横竖屏与 Safe Area

iPad Web App 不应依赖强制锁屏方向作为正确体验的前提。测试应覆盖横屏主布局和竖屏回退，并重点观察圆角、状态区域与底部系统手势区。Screen Orientation API 的部分行为仍可能因设备与浏览器模式而异，因此布局必须自行适配。[3]

| ID | 操作 | 预期结果 | 级别 | 结果 |
|---|---|---|---|---|
| F-01 | 在 Home Screen Web App 横屏启动，完整浏览首关。 | 方向键、工具栏、关卡信息与迷宫均完整可见；按钮没有贴在圆角或底部手势区。 | 阻断 |  |
| F-02 | 在游戏中旋转为竖屏，再旋转回横屏。 | 布局及时重排，画布不拉伸变形；所有关键控件仍可点击；游戏位置、步数和本地进度不丢失。 | 高 |  |
| F-03 | 在分屏或舞台调度允许的设备上，将 Web App 缩到约半屏后恢复全屏。 | 应用不崩溃；控件可见或以可理解方式折叠；恢复后迷宫与输入继续正常。 | 中 |  |
| F-04 | 用单手分别点击屏幕四角附近、底部方向键和顶部家长按钮。 | 无系统手势遮挡或误触；控件不被裁切，按下反馈清晰。 | 阻断 |  |
| F-05 | 在“设置 → 辅助功能 → 动态效果”开启减少动态效果后重开。 | 动效减弱但成功、碰撞、提示和关卡状态仍可理解。 | 中 |  |

## 4. 离线与缓存恢复

离线测试必须先完成一次联网首开，让应用壳与首关资源进入缓存。随后先关闭 Web App，再断开网络，从主屏幕重新启动；不要只在已经打开的页面中切离线。该流程验证 Service Worker 的缓存是否真的支持独立启动，而非仅验证内存中的已加载资源。

| ID | 操作 | 预期结果 | 级别 | 结果 |
|---|---|---|---|---|
| L-01 | 在线启动 Home Screen Web App，进入首关并完成至少一次移动；关闭 Web App。 | 本地已记录当前关卡与基础进度。 | 前置 |  |
| L-02 | 关闭 Wi‑Fi；蜂窝版 iPad 同时关闭蜂窝数据。确认浏览器无法打开新的网页。 | 设备处于完全离线状态。 | 前置 |  |
| L-03 | 从主屏幕重新打开游戏。 | 游戏在离线状态下进入已缓存的应用壳与首关；不会停在“无网络”浏览器错误页。 | 阻断 |  |
| L-04 | 离线完成若干移动、使用撤销/重来、切换静音，再关闭并重开。 | 交互和本地进度可用；不因网络请求失败导致卡死。未缓存的远端字体可降级为系统字体，不应影响操作。 | 高 |  |
| L-05 | 离线打开家长面板并查看周报。 | 本地数据可读；界面不因网络缺失出现报错。 | 高 |  |
| L-06 | 离线尝试进入尚未加载过的主题/关卡资源。 | 若资源已按需缓存，应正常进入；若未缓存，应给出可理解的回退，不得白屏或清空存档。记录实际行为。 | 中 |  |
| L-07 | 恢复网络后关闭并重新启动游戏。 | 应用恢复联网；不丢失离线期间的本地进度。 | 阻断 |  |

若 L-03 失败，按以下顺序排查：确认 URL 为 HTTPS；确认曾在联网状态完整打开过；从 iPad 设置中查看该网站的数据是否被清除；在 Safari 重新访问并确认主屏幕图标仍指向正确域名。不要通过清空所有浏览数据来掩盖问题，除非该操作被记录为一次独立复测。

## 5. 后台恢复、更新与多次启动

Home Screen Web App 应像普通 App 一样处理后台与版本变更。更新提示必须由家长主动触发；儿童在关卡中不能被强制刷新。WebKit 说明主屏幕 Web App 可独立显示在 App Switcher 中。[1]

| ID | 操作 | 预期结果 | 级别 | 结果 |
|---|---|---|---|---|
| R-01 | 游戏进行到中途，回到主屏幕，等待 30 秒后从 App Switcher 恢复。 | 关卡、角色位置和 UI 状态可继续使用；无黑屏或重复初始化。 | 高 |  |
| R-02 | 游戏进行到中途，切换至其他 App 5 分钟后返回。 | 若系统未回收进程，应保持状态；若被回收，应至少恢复到已保存的当前关卡且不损坏进度。 | 高 |  |
| R-03 | 已安装旧版时发布一个新预览/生产版本；联网重开 Web App 后进入家长面板。 | 仅家长面板出现“森林里有新内容”；点击“立即更新”后重新加载新版本，本地存档保留。 | 高 |  |
| R-04 | 不点击更新，继续完成当前关卡。 | 当前会话不被强制刷新；退出后再启动时可获取新版本。 | 高 |  |
| R-05 | 连续从主屏幕启动与关闭 10 次。 | 每次可用，无越来越慢、资源丢失或多次注册异常。 | 中 |  |

## 6. 儿童可用性观察

此组不以“儿童完成速度”作为分数，而以是否能在不解释的条件下理解入口、操作和结果为依据。开始前征得家长同意，不收集姓名、照片、录音或可识别信息；仅记录聚合观察和匿名任务结果。

| ID | 任务 | 观察点 | 通过信号 |
|---|---|---|---|
| C-01 | 让儿童从 iPad 主屏幕自己打开游戏。 | 是否能认出图标并进入。 | 无成人操作提示即可进入首关。 |
| C-02 | 让儿童完成一关迷宫。 | 是否理解方向键、碰墙与提示；是否发生连续误触。 | 在少量自然探索后可自行完成或主动使用提示。 |
| C-03 | 让儿童旋转 iPad 或短暂离开再回来。 | 是否把旋转/恢复视为“游戏坏了”。 | 返回后能继续，不出现困惑或成人求助。 |
| C-04 | 让儿童再次打开应用。 | 是否被安装/更新/设置流程干扰。 | 直接回到游戏；家长功能不成为儿童误触热点。 |
